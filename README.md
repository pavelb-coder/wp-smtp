# WP SMTP-KV

Плагин WordPress для отправки почты через SMTP-сервер с авторизацией. Настраивает экземпляр PHPMailer, который использует `wp_mail()`, поэтому письма ядра, форм, восстановления пароля и WooCommerce идут через указанный сервер.

Репозиторий: https://github.com/pavelb-coder/wp-smtp

## Возможности

- Хост, порт, шифрование (`none` / `ssl` / `tls`), SMTP AUTH, логин и пароль.
- Пароль хранится зашифрованным: AES-256-CBC, ключ выводится из `wp_salt('auth')`, IV случайный. Поле пароля никогда не подставляется обратно в форму; пустое поле = «не менять».
- Принудительная подмена `From` (адрес и имя) для всех писем.
- Таймаут соединения и отладочный лог диалога с сервером в `error_log`.
- Кнопка «Отправить тест»: работает даже когда SMTP выключен, показывает текст ошибки PHPMailer.
- Страница **Настройки → WP SMTP-KV**, проверка `manage_options`, nonce, санитизация и экранирование, удаление настроек при удалении плагина.

## Установка

1. Скопируйте папку `wp-smtp` в `wp-content/plugins/` (или установите архив `wp-smtp-1.0.1.zip` через «Плагины → Добавить новый»).
2. Активируйте **WP SMTP-KV**.
3. Откройте «Настройки → WP SMTP-KV», заполните хост, порт, шифрование, логин и пароль.
4. Поставьте галочку «Использовать SMTP», сохраните и отправьте тестовое письмо.

Требования: WordPress 5.8+, PHP 7.4+, расширение OpenSSL. Без OpenSSL пароль сохраняется в открытом виде — такой сервер не стоит использовать для боевой почты.

## Параметры популярных провайдеров

| Провайдер | Хост | Порт | Шифрование | Логин |
| --- | --- | --- | --- | --- |
| Yandex 360 / Почта | `smtp.yandex.ru` | 465 | SSL | полный адрес почты |
| Gmail | `smtp.gmail.com` | 587 | TLS | адрес Gmail, пароль = App Password |
| Mail.ru | `smtp.mail.ru` | 465 | SSL | полный адрес почты |
| Хостинг (Timeweb, Beget, reg.ru и др.) | `smtp.<домен>` | 465 или 587 | SSL или TLS | адрес ящика на домене |

Адрес в поле «E-mail отправителя» должен совпадать с аккаунтом SMTP: большинство серверов отклоняют письма с чужим `From`.

## Версионирование (формат `x.y.z`)

Плагин использует SemVer: **`MAJOR.MINOR.PATCH`**, только три неотрицательных числа без префиксов и суффиксов (`1.0.0`, `1.2.3`, `2.0.0`; не `v1.0`, не `1.0`, не `1.0.0-beta`).

- `x` (major) — несовместимые изменения: смена формата настроек, удаление хуков, новый минимум PHP/WordPress.
- `y` (minor) — новая функциональность с обратной совместимостью: новые поля, новые хуки.
- `z` (patch) — исправления, безопасность, правки документации без изменения поведения.

WordPress требует литерал версии в заголовке плагина и в `readme.txt`, поэтому одна и та же версия продублирована в четырёх местах, а `VERSION` служит источником истины для скриптов:

| Где | Что |
| --- | --- |
| `VERSION` | `1.0.1` — читают инструменты |
| `wp-smtp.php` | `Version: 1.0.1` и `WP_SMTP_VERSION` |
| `readme.txt` | `Stable tag: 1.0.1` и раздел `= 1.0.1 =` в Changelog |
| архив | `wp-smtp-1.0.1.zip` в корне рабочей папки |

Команды (из каталога плагина):

```bash
python3 tools/version.py check          # все четыре места совпадают и формат x.y.z?
python3 tools/version.py show           # текущая версия
python3 tools/version.py bump patch     # 1.0.1 -> 1.0.2 (или minor / major / 2.1.0)
python3 tools/version.py pack           # собрать ../wp-smtp-1.0.1.zip
```

`bump` сам обновляет заголовок, константу, `Stable tag`, добавляет заготовку в Changelog и перезаписывает `VERSION`. `pack` сначала запускает `check` и не соберёт архив при расхождении версий; в архив не попадают `.git`, `tools/`, `tests/`, `VERSION`, логи и временные файлы (см. `.distignore`).

## Проверка перед отправкой

```bash
bash tools/check.sh     # version.py check + php -l + smoke-тест + git status
```

Скрипт не требует установленного WordPress: `tests/test-options.php` подменяет несколько функций WP и проверяет шифрование пароля, значения по умолчанию и очистку опций. Архив собирается отдельно: `python3 tools/version.py pack`.

## Как это работает

```php
add_action( 'phpmailer_init', array( $mailer, 'configure_phpmailer' ), 999 );
```

В хуке выставляются `isSMTP()`, `Host`, `Port`, `SMTPAuth`, `Username`, `Password`, `SMTPSecure`, `Timeout`. Фильтры `wp_mail_from` и `wp_mail_from_name` подменяют отправителя, если включена соответствующая опция.

## Безопасность

- Используйте пароли приложений (app password), а не пароль аккаунта.
- Не включайте отладку на продакшене: в `error_log` попадёт SMTP-диалог.
- Шифрование пароля защищает от «просто прочитать базу», но не от executable-кода на сайте: берегите `wp-config.php` и доступ администратора.
- В репозиторий не кладутся реальные пароли, токены и `wp-config.php`.

## Типичные проблемы

| Симптом | Что проверить |
| --- | --- |
| `Could not connect to SMTP host` | Хост/порт, исходящие порты 465/587 у хостера, DNS |
| `SMTP Error: Could not authenticate` | Логин (часто нужен полный e-mail), app password, SMTP AUTH |
| `Certificate mismatch` | Домен в хосте и сертификат, не отключайте проверку TLS без причины |
| Письмо уходит, но не доходит | `From`, SPF/DKIM/DMARC домена, папка «Спам» |
